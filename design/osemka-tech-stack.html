01 · Stack

Three decisions that drive the rest

TypeScript everywhere

The importer, scoring and app share one Zod schema. A task the importer writes is validated by the same code that later renders and scores it.

Windows and macOS

Every dependency has to work on both. Mac-only tools are replaced, paths are handled the same way on both systems, and every change is tested on both in CI.

Scoring is pure code

Scoring and analytics are plain functions with no UI or database inside, so they can be tested against real key entries before any screen exists.

03 · Stack

Windows support

Two kinds of work: the app has to run and look right on a typical Windows laptop, and the importer has to cope with Windows paths.

File paths with Polish letters

Found in your folders. On this Mac, Język polski and Język angielski are stored in decomposed Unicode (NFD: “e” followed by a separate ogonek mark), while Matematyka has no special letters. Windows normally uses composed form (NFC). Copying the folders between systems can produce either form, so a plain string comparison of paths will fail on one of them.
  • Content files store paths relative to the data folder, with forward slashes and NFC letters.
  • At runtime, folder and file names are matched by comparing NFC forms of the directory listing, never by building the exact string.
  • Paths are always joined with Node's path module, never with “/” by hand.
  • .gitattributes fixes line endings to LF, so files look the same on both systems.
  • Project scripts are written in Node, not shell commands like rm -rf, so they run in PowerShell too.
  • The project should live close to the drive root (e.g. C:\osemka) to stay clear of Windows' 260-character path limit.

Windows laptops and screens

  • Small screens: many school laptops are 1366×768 at 125 % scaling, which leaves about 1093×615 px. The simulation screen must fit that without scrolling the header; below 1200 px wide the sheet map becomes a drawer.
  • High contrast mode: styles respond to forced-colors, and answer states already use an icon and a word, not color alone.
  • Scrollbars take space on Windows: reading panes use scrollbar-gutter: stable so the text doesn't jump.
  • Fonts are bundled with the app (no internet needed); Segoe UI is the fallback.
  • Shortcut hints show Ctrl on Windows and ⌘ on macOS.
  • One engine: Electron brings its own Chromium, so the app looks and behaves the same on every PC regardless of the installed browser.

How the desktop app works

TopicDecision
InstallerNSIS .exe from electron-builder, per-user install (no administrator rights needed), Start menu and desktop shortcut, uninstaller. macOS gets a .dmg.
Where it's builtThe Windows installer is built on Windows (a GitHub Actions Windows runner, or a Windows PC), because the SQLite module has to be compiled for Windows and Electron. The Mac app is built on this Mac.
What's insideThe app, the published content/, and the source files the app shows: sheet PDFs for the PDF panel and the six recordings. The six sessions' source files are 55 MB today; with Electron the installer is roughly 150 MB and about 350 MB once installed (estimate, measured in P9).
Student data%APPDATA%\Osemka\ on Windows, ~/Library/Application Support/Osemka/ on macOS: the database and settings. The folder name has no Polish letters on purpose. Uninstalling keeps the data unless the student ticks “usuń dane”.
BackupUstawienia → Dane → “Eksportuj” writes one file with all attempts; “Importuj” restores it on another PC.
New examsThe importer stays a developer tool. New sessions (e.g. Maj 2027) reach the student as a new app version.
Updatesv1: download and run the new installer, data is kept. Later: automatic updates with electron-updater from a release server.
AI keyOptional. Entered once in Ustawienia, stored encrypted with Electron safeStorage (Windows DPAPI, macOS Keychain), used only by the main process. Without a key, self-grading works and AI suggestions are hidden.
Code signingv1 unsigned: Windows shows “System Windows ochronił ten komputer” on first run, and the student clicks “Więcej informacji” → “Uruchom mimo to”. To remove the warning, sign with Microsoft's Trusted Signing service (small monthly fee) or a code-signing certificate.

Where AI is used, and how

Two jobs, both through the official Anthropic TypeScript SDK. Import runs on the developer's machine; grading suggestions run in the app's main process, never in the window.

Import: PDF → tasks and keysGrading suggestions
ModelClaude Opus 5.5 (claude-opus-5-5)Claude Opus 5.5
InputThe task's PDF pages as a document, plus its text layerStudent's answer, the key's criteria and the sample solutions
OutputStructured JSON checked against the Zod schemaStructured JSON: points per criterion + a short reason quoting the key
Efforthigh: accuracy matters, it runs once per sessionmedium: answer within seconds
Cost controlsBatch API (half price, not time-sensitive); the shared instructions and schema are cachedRubric and key excerpt cached per task
Safety netValidation, then human review before publishingShown as a suggestion only; the student decides

Rough cost: a few US dollars to import all six sessions, and well under one cent per essay suggestion. Both are estimates to confirm by measuring on the first session.

First step

The project folder is not a git repository yet. P0 starts with git init, a .gitignore that keeps the source PDFs and recordings out of the repository (they are large and come from CKE), a .gitattributes for line endings, and the workspace skeleton. The Windows CI run needs the repository on GitHub; until then, Windows checks are manual. Then P1 starts on Matematyka · Maj 2026.
