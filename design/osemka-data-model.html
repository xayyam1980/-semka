02 · Principles

Five modeling rules

The item is the unit

Scores, skill tags and analytics live on items (“8.1”, “2.3”), not tasks. English task 1 alone tests four different requirements across its items.

Content is immutable

A published session never changes. A re-import creates a new content version, and each attempt keeps the version it was taken on, so old scores never shift.

Every point has a source

Each score records whether it came from auto-checking, the student, or an accepted AI suggestion. Analytics can filter on this.

Always traceable to paper

Every task, stimulus and key entry carries a page reference to the original PDF, for students and for reviewers.

Derived data is computed

Skill stats, readiness and trends are computed from responses and scores. Nothing in analytics is stored by hand.

05 · Model

Scoring engine

Each response type maps to one rule. Only some can be fully automatic; the rest go to the self-grading queue.

Response typeWhereRuleChecked by
single_choiceallmatch key for the attempt's versionauto
true_falsePL, MAall_or_nothing (“oba zdania muszą być dobrze”)auto
choice_with_reasonPL, MAall_or_nothing on choice + reasonauto
matchingENper_part, 1 pt per slotauto
short_textEN, PLtext_match with strictnessauto when listed, otherwise self
worked_solutionMAlevels with LUB paths + exemplarsself, AI optional
extended_textPL essay, EN e-mailrubric with gates, error counts, matrixself, AI optional

Short-answer matching

  1. Normalize: trim, collapse spaces, unify quotes and apostrophes, fold case (the key accepts capital/lowercase swaps).
  2. Answer matches an expected or accepted answer: correct, scored automatically.
  3. Answer matches a rejected example: incorrect, and the key's reason is shown.
  4. Anything else: unresolved. The student compares it with the key, optionally with an AI suggestion, and the score is saved as self-graded.
No fuzzy auto-credit. The key itself rejects “snakes” for “snacks”, which is one letter apart. Near-matches are only used to show the closest accepted answer during self-check, never to award points.

06 · Model

Student layer

 Attempt lifecycle

   [in_progress] ──Oddaj / czas minął──► [submitted] ──ostatnie zadanie otwarte ocenione──► [graded]
        │  ▲                                  │
   wyjście│  │Wznów (tylko nauka)            wynik tymczasowy: punkty auto
        ▼  │                                  + „?” przy zadaniach do samooceny
     (zapisane)
  • Deadline-based timer. A simulation stores deadlineAt at start. Remaining time is always deadline minus now, so reloading, closing the tab or a sleeping laptop cannot add time. On reopen after the deadline, the attempt is submitted with submitReason: "time_up".
  • Accommodation snapshot. Extended time and dyslexia thresholds are copied into the attempt at start, so changing settings later doesn't rescore old attempts.
  • Responses save on every change, simulation mode every 5 s at most. Flags, hints used, highlights and time per item are stored with the answer.
  • Event log is append-only: views, checks, focus changes, audio play and seek. It feeds time-per-task stats and proves that exam audio rules were followed.
07 · Model

How the analytics are computed

Skill resultper tag, per window
pct = Σ earned / Σ maxPoints over scored items with the tag
n < 4 → “za mało danych”; unscored items are left out
Status
opanowane ≥ 80 % · do pracy 50–79 % · słabe < 50 %
Improvement
Change vs the previous window of the same length, reported only when both windows have n ≥ 4.
Subject estimate
weighted mean of the last 3 attempts' %
weights: recency 3·2·1 × mode (symulacja 1.0, nauka 0.5) × share of the sheet covered
Readiness
Mean of the 3 subject estimates. Confidence is high when every subject has a simulation in the last 30 days, medium when two do, low otherwise.
Next step
recoverable(area) = avg maxPoints per session in area × (1 − pct)
pick the area with the highest value and n ≥ 4

08 · Import

From PDF to published session

The PDFs have a real text layer, so most of the structure can be found reliably. Formulas and figures are the exception: in the text layer, fractions like 48 km / 40 min break across lines. Those parts use page images and an AI vision model, and everything is checked by a person before it is published.

09 · Import

Audio cue map

The recording is about 21 minutes and contains every text twice, plus instructions and pauses. Practice mode needs to know where each piece starts.

  1. Transcribe the mp3 with word-level timestamps using whisper.cpp, which runs locally on Windows and macOS.
  2. Align the result with transkrypcja.pdf, which labels “Zadanie 1. Tekst 1” and so on.
  3. Each text is found twice: the first match is play1, the second play2. Silent gaps between them become pause; Polish instructions become instruction.
  4. The reviewer checks the boundaries on a waveform and nudges them if needed.
 0:00 ┃intro┃ instr. Z1 ┃ T1 play1 ┃pause┃ T1 play2 ┃pause┃ T2 play1 ┃ … ┃ instr. Z4 ┃ … ┃ outro ┃ 21:24

Simulation mode ignores the segments and plays the file once from 0:00, so it stays faithful even if a boundary is slightly off.

10 · Import

Checks before publishing

  • Sum of task points equals the session total, and each task equals the sum of its items.
  • Task numbers run 1…N without gaps, and the sheet and key list the same tasks.
  • Every item has a key for each sheet version, or is marked as the same for all versions.
  • Choice keys point to options that exist.
  • Rubric criteria add up to the item's points (20 for the essay, 10 for the e-mail).
  • Every item has at least one skill tag, and every tag has a display area.
  • Page references fall within the file's page count; every figure file exists.
  • Line numbers cited in tasks exist in the stimulus.
  • Audio segments are sorted, don't overlap, end before the file does, and every listening task has both plays.

// Ósemka data model, v1 (2026-11-16)
// Two layers:
//   CONTENT  - built by the importer from the CKE PDFs/MP3, immutable once published,
//              versioned by content hash. Stored as JSON files + assets.
//   STUDENT  - attempts, responses, scores. Every attempt pins a content version.
// Derived analytics (skill stats, readiness) are computed from STUDENT + CONTENT, never typed in.

// ───────────────────────── CONTENT ─────────────────────────

export type SubjectId = "polski" | "matematyka" | "angielski";
export type SheetVersion = "X" | "Y";             // keys list answers per version
export type Term = "glowny" | "dodatkowy";         // termin główny / dodatkowy

export interface Subject {
  id: SubjectId;
  name: string;                // "Język polski"
  examCode: string;            // "OPOP" | "OMAP" | "OJAP" (prefix of form codes)
  standardMinutes: number;     // 150 | 125 | 110
  extendedMinutesDefault: number; // 225 | 185 | 165 (editable, confirm vs CKE notice)
}

/** One exam sitting, e.g. Matematyka · Maj 2026 · termin główny. Maps 1:1 to a folder. */
export interface Session {
  id: string;                  // "matematyka-2026-05-glowny"
  subjectId: SubjectId;
  year: number;                // 2026
  month: number;               // 5  (parsed from folder "Maj 2026")
  term: Term;                  // from key header, default "glowny"
  examDate?: string;           // "2026-05-13" (from key header "Termin egzaminu")
  formCode: string;            // "OJAP-100" - only the standard form is imported
  versions: SheetVersion[];    // ["X","Y"]
  maxPoints: number;           // 45 | 30 | 55, must equal sum of tasks
  taskOrder: string[];         // task ids in sheet order
  sources: SourceFile[];
  contentVersion: string;      // sha256 over the normalized session JSON
  status: "draft" | "reviewed" | "published";
}

export type SourceKind =
  | "arkusz"                 // arkusz.pdf
  | "karta_otwarte"          // arkusz-zadania-otwarte.pdf (answer sheet for open tasks)
  | "klucz"                  // klucz.pdf | odpowiedzi.pdf | zasady_oceniania.pdf
  | "nagranie"               // *.mp3
  | "transkrypcja";          // transkrypcja.pdf

export interface SourceFile {
  kind: SourceKind;
  /** Relative to the data folder, forward slashes, Unicode NFC: "Matematyka/Maj 2026/klucz.pdf".
   *  On disk the name may be NFD (macOS) or NFC (Windows): resolve by comparing NFC forms. */
  path: string;
  sha256: string;
  pages?: number;
  durationSec?: number;      // audio only
}

/** Pointer back to the original, used by "Arkusz PDF, s. 6" and by reviewers. */
export interface PageRef {
  source: SourceKind;
  page: number;              // 1-based
  bbox?: [x: number, y: number, w: number, h: number]; // PDF points, optional crop
}

/** Shared material that several tasks refer to: a passage, a chart, a recording segment. */
export interface Stimulus {
  id: string;                // "pl-2026-tekst-2"
  kind: "text" | "poem" | "figure" | "table" | "audio";
  title?: string;
  author?: string;           // literary texts
  /** Text kept as lines so line numbers match the arkusz ("w. 12–14"). */
  lines?: string[];
  lineNumbering?: "every" | "every5" | "none";
  asset?: string;            // "assets/ma-2026-z7.svg" for figures
  audioSegmentIds?: string[];
  ref: PageRef;
}

/** A numbered task as printed: "Zadanie 8. (0–3)". */
export interface Task {
  id: string;                // "pl-2026-08"
  sessionId: string;
  number: number;            // 8
  maxPoints: number;         // 3  (= sum of its items' maxPoints)
  instruction: string;       // polecenie, Markdown + LaTeX
  stimulusIds: string[];
  items: Item[];             // at least one
  format: "zamkniete" | "otwarte";
  skillTags: string[];       // inherited by items unless the item overrides
  section?: string;          // English: "Rozumienie ze słuchu", ...
  ref: PageRef;
}

/** Smallest scored unit: "8.1", "1.3", or the whole task when it has no sub-items. */
export interface Item {
  id: string;                // "pl-2026-08-1"
  label: string;             // "8.1"
  maxPoints: number;
  prompt?: string;
  response: ResponseSpec;
  key: Partial<Record<SheetVersion, KeySpec>>; // version-specific where the key splits
  scoring: ScoringRule;
  skillTags?: string[];      // e.g. English 1.1 = II.5, 1.2 = II.4
  explanation?: string;      // shown in practice mode after checking
  exemplars?: Exemplar[];    // "Przykładowe rozwiązania ocenione na 3 punkty"
}

// How the student answers (drives the input component)
export type ResponseSpec =
  | { type: "single_choice"; options: Option[] }                 // A–D
  | { type: "true_false"; statements: Option[] }                 // P/F per statement
  | { type: "matching"; slots: string[]; options: Option[] }     // 2.1–2.4 → A–E
  | { type: "choice_with_reason"; choices: Option[]; reasons: Option[] } // A/B + 1/2/3
  | { type: "short_text"; gaps: number; language: "pl" | "en" } // gap fill, short answer
  | { type: "worked_solution" }                                  // math open: typed or on paper
  | { type: "extended_text"; minWords?: number; form?: string }; // essay, e-mail

export interface Option { id: string; text: string; asset?: string }

// What counts as correct
export type KeySpec =
  | { type: "choice"; correct: string }                          // "C"
  | { type: "choices"; correct: Record<string, string> }         // {"P1":"P","P2":"F"} or {"2.1":"C"}
  | { type: "text"; expected: string[]; accepted: string[]; rejected: RejectedExample[] }
  | { type: "model_solution"; solution: string };                // Markdown + LaTeX

export interface RejectedExample { answer: string; reason: string } // "snakes" - zmienia znaczenie

export type ScoringRule =
  | { type: "all_or_nothing" }                       // 1 pkt only if every part correct
  | { type: "per_part"; pointsEach: number }         // English 2.1–2.4: 1 pkt each item
  | { type: "text_match"; strictness: TextStrictness }
  | { type: "levels"; levels: Level[] }              // math open 0–3, Polish short open
  | { type: "rubric"; rubricId: string };            // essay / e-mail

/** English key: środki językowe need full correctness; listening/reading only need the message. */
export type TextStrictness = "communicative" | "strict_spelling";

export interface Level {
  points: number;            // 3, 2, 1, 0
  /** Alternatives joined by "LUB" in the key; any one satisfies the level. */
  paths: string[];
}

export interface Exemplar { points: number; content: string; note?: string; ref: PageRef }

/** Essay (PL zad. 18, 0–20) and e-mail (EN zad. 14, 0–10). */
export interface Rubric {
  id: string;
  maxPoints: number;
  criteria: Criterion[];
  /** e.g. "Realizacja tematu = 0 → all other criteria = 0". */
  gates: { ifCriterion: string; equals: number; thenAllOthers: number }[];
}

export type Criterion =
  | { id: string; name: string; type: "levels"; max: number; levels: Level[] }
  | {
      // Ortografia, Interpunkcja: points from an error count, two threshold sets
      id: string; name: string; type: "error_count"; max: number;
      thresholds: { standard: Threshold[]; dyslexia: Threshold[] };
    }
  | {
      // EN Treść: points from (podpunkty referenced × podpunkty developed)
      id: string; name: string; type: "matrix"; max: number;
      rows: string; cols: string; table: Record<string, Record<string, number>>;
    };

export interface Threshold { maxErrors: number; points: number } // first match wins

/** A curriculum requirement exactly as the key prints it, plus a display area for analytics. */
export interface SkillTag {
  id: string;                // "ma-XII.9" | "en-II.5" | "pl-I"
  subjectId: SubjectId;
  stage?: "IV–VI" | "VII–VIII";
  general: string;           // "IV. Rozumowanie i argumentacja."
  specific?: string;         // "XII. Obliczenia praktyczne. 9) ... prędkość ..."
  area: string;              // display group, mapped by hand: "Obliczenia praktyczne"
}

/** Listening: one entry per contiguous piece of the full CKE recording. */
export interface AudioSegment {
  id: string;                // "en-2026-z1-t2-play1"
  recording: string;         // SourceFile path
  startSec: number;
  endSec: number;
  role: "intro" | "instruction" | "play1" | "pause" | "play2" | "outro";
  taskNumber?: number;       // 1
  textLabel?: string;        // "Tekst 2"
  transcriptLines?: string[];
}

  theme: "system" | "light" | "dark";
  fontScale: number;                 // 0.9–1.4
  readingFont: "literata" | "sans" | "dyslexic";
  reduceMotion: boolean;
  extendedTime: boolean;

  /** Simulation only. The countdown is deadline-based, so reloads and closed tabs keep time. */
  deadlineAt?: string;
  timeLimitMin?: number;             // 125 or 185, copied from settings at start
  accommodations: { extendedTime: boolean; dyslexiaCriteria: boolean }; // snapshot

  submitReason?: "student" | "time_up";

}

  attemptId: string;
  itemId: string;
  value: ResponseValue | null;
  flagged: boolean;
  hintsUsed: number;
  timeSpentMs: number;
  checkedAt?: string;                // practice: when "Sprawdź" was pressed
